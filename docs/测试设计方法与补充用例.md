## 一、测试设计方法选择

### 1.1 方法概述

本系统功能测试采用以下测试设计方法，根据不同功能模块的特点选择合适的方法或方法组合：

| 序号 | 设计方法 | 适用场景 | 本系统应用模块 |
|------|----------|----------|----------------|
| 1 | 等价类划分法 | 输入条件有明确取值范围或集合 | 用户注册、登录、评价评分、数量输入 |
| 2 | 边界值分析法 | 输入/输出存在边界条件 | 价格区间、库存数量、密码长度、地址数量 |
| 3 | 判定表法 | 多个条件组合影响结果 | 商家审核状态、订单状态流转、用户权限 |
| 4 | 状态迁移法 | 系统存在明确的状态转换 | 订单生命周期、商家审核流程、图书上下架 |
| 5 | 场景法 | 涉及多个步骤的业务流程 | 购物流程、下单支付流程、评价流程 |
| 6 | 错误推测法 | 基于经验推测可能的错误 | 接口异常、并发操作、数据越权 |
| 7 | 因果图法 | 输入条件之间有组合关系 | 注册表单验证、地址表单验证 |

### 1.2 各方法详细说明

#### 1.2.1 等价类划分法

**原理**：将输入数据划分为若干等价类，从每个等价类中选取一个代表性数据作为测试用例。

**应用示例 — 用户注册（U-001）**：

| 等价类类型 | 输入项 | 有效等价类 | 无效等价类 |
|------------|--------|------------|------------|
| 用户名 | username | 4-20位字母数字组合 | 空、<4位、>20位、特殊字符、纯数字 |
| 密码 | password | 6-20位，含字母和数字 | 空、<6位、>20位、纯字母、纯数字 |
| 确认密码 | confirmPassword | 与密码一致 | 与密码不一致 |

**应用示例 — 评价评分（U-048）**：

| 等价类类型 | 有效等价类 | 无效等价类 |
|------------|------------|------------|
| 评分 | 1、2、3、4、5 | 0、6、-1、小数、空 |

#### 1.2.2 边界值分析法

**原理**：选取输入/输出范围的边界值及其邻近值作为测试用例。

**应用示例 — 密码长度**：

| 边界点 | 测试值 | 预期结果 |
|--------|--------|----------|
| 最小长度-1 | 5位密码 | 注册失败，提示密码长度不足 |
| 最小长度 | 6位密码 | 注册成功 |
| 最小长度+1 | 7位密码 | 注册成功 |
| 最大长度-1 | 19位密码 | 注册成功 |
| 最大长度 | 20位密码 | 注册成功 |
| 最大长度+1 | 21位密码 | 注册失败，提示密码过长 |

**应用示例 — 购买数量**：

| 边界点 | 测试值 | 预期结果 |
|--------|--------|----------|
| 最小值-1 | 0 | 提示数量不能为0 |
| 最小值 | 1 | 添加成功 |
| 最小值+1 | 2 | 添加成功 |
| 库存值-1 | 库存-1 | 添加成功 |
| 库存值 | 库存数量 | 添加成功 |
| 库存值+1 | 库存+1 | 提示库存不足 |

#### 1.2.3 判定表法

**原理**：列出所有条件和动作，分析条件组合与动作之间的对应关系。

**应用示例 — 商家登录判定表**：

| 条件\规则 | R1 | R2 | R3 | R4 | R5 |
|-----------|----|----|----|----|----|
| 账号存在 | Y | Y | Y | Y | N |
| 密码正确 | Y | Y | Y | N | - |
| 审核状态=待审核 | Y | N | N | - | - |
| 审核状态=正常 | N | Y | N | - | - |
| 审核状态=已拒绝 | N | N | Y | - | - |
| **动作：登录成功** | | ✓ | | | |
| **动作：提示审核中** | ✓ | | | | |
| **动作：提示已拒绝** | | | ✓ | | |
| **动作：提示密码错误** | | | | ✓ | |
| **动作：提示账号不存在** | | | | | ✓ |

**应用示例 — 订单取消判定表**：

| 条件\规则 | R1 | R2 | R3 | R4 |
|-----------|----|----|----|----|
| 订单属于当前用户 | Y | Y | Y | N |
| 订单状态=待付款 | Y | N | N | - |
| 订单状态=待发货 | N | Y | N | - |
| 订单状态=已发货/已完成 | N | N | Y | - |
| **动作：取消成功，恢复库存** | ✓ | | | |
| **动作：取消成功，不恢复库存** | | ✓ | | |
| **动作：提示不可取消** | | | ✓ | |
| **动作：提示无权操作** | | | | ✓ |

#### 1.2.4 状态迁移法

**原理**：分析系统对象的状态及其迁移条件，覆盖所有合法状态迁移路径。

**应用示例 — 订单状态迁移图**：

```
                    ┌──────────────────────┐
                    │                      │
                    ▼                      │
┌──────────┐  提交订单  ┌──────────┐  模拟支付  ┌──────────┐
│  初始状态 │ ────────→ │  待付款   │ ────────→ │  待发货   │
└──────────┘           └──────────┘           └──────────┘
                         │                      │
                      取消订单                商家发货
                         │                      │
                         ▼                      ▼
                    ┌──────────┐           ┌──────────┐
                    │  已取消   │           │  已发货   │
                    └──────────┘           └──────────┘
                                              │
                                           确认收货
                                              │
                                              ▼
                                         ┌──────────┐
                                         │  已完成   │
                                         └──────────┘
```

**状态迁移测试用例**：

| 编号 | 迁移路径 | 测试步骤 | 预期结果 |
|------|----------|----------|----------|
| ST-01 | 初始→待付款 | 提交订单 | 订单创建成功，状态为待付款 |
| ST-02 | 待付款→待发货 | 模拟支付 | 支付成功，状态变为待发货 |
| ST-03 | 待付款→已取消 | 取消订单 | 订单取消，库存恢复 |
| ST-04 | 待发货→已发货 | 商家发货 | 状态变为已发货 |
| ST-05 | 已发货→已完成 | 确认收货 | 状态变为已完成 |
| ST-06 | 已发货→待付款 | 尝试回退 | 不允许，操作失败 |
| ST-07 | 已完成→待发货 | 尝试回退 | 不允许，操作失败 |
| ST-08 | 已取消→待付款 | 尝试回退 | 不允许，操作失败 |

#### 1.2.5 场景法

**原理**：模拟用户实际操作场景，覆盖基本流、备选流和异常流。

**应用示例 — 完整购物流景**：

```
基本流（Happy Path）：
  用户登录 → 浏览图书 → 加入购物车 → 去结算 → 选择地址 → 提交订单
  → 模拟支付 → 商家发货 → 确认收货 → 提交评价 → 商家回复

备选流1：从详情页直接购买（跳过购物车）
备选流2：修改购物车商品数量后结算
备选流3：只选择部分商品结算
备选流4：取消订单后重新下单
备选流5：无收货地址时先添加地址再下单

异常流1：库存不足时下单
异常流2：商品已下架时下单
异常流3：Token过期时操作
异常流4：重复提交订单
```

#### 1.2.6 错误推测法

**原理**：基于经验和直觉，推测程序中可能存在的错误，设计针对性测试用例。

**推测的常见错误**：

| 序号 | 推测错误 | 测试用例 |
|------|----------|----------|
| 1 | 并发下单导致超卖 | 同一用户快速多次点击提交订单 |
| 2 | 删除商品后订单详情异常 | 下单后商家删除该图书，查看历史订单 |
| 3 | 价格篡改 | 前端修改价格参数后提交订单 |
| 4 | 越权访问 | 用户A查看/操作用户B的订单 |
| 5 | XSS注入 | 在评价内容中输入 `<script>` 标签 |
| 6 | SQL注入 | 在搜索框输入 `' OR 1=1 --` |
| 7 | 空指针异常 | 不选商品直接点击结算 |
| 8 | 重复提交 | 快速连续点击提交按钮 |

## 四、测试设计方法选择依据

针对本系统各模块选择设计方法的依据：

| 功能模块 | 主要方法 | 选择理由 |
|----------|----------|----------|
| 用户注册/登录 | 等价类 + 边界值 | 输入项有明确的格式和长度要求 |
| 图书搜索 | 等价类 + 错误推测 | 需验证正常搜索、空值、注入攻击 |
| 购物车 | 边界值 + 场景法 | 数量有上下限，操作有多种组合场景 |
| 订单流程 | 状态迁移 + 场景法 | 订单有明确的状态流转，涉及多步骤业务 |
| 商家审核 | 判定表 + 状态迁移 | 多条件组合决定审核结果 |
| 收货地址 | 边界值 + 判定表 | 地址数量有上限，删除默认地址有特殊逻辑 |
| 评价功能 | 等价类 + 错误推测 | 评分有范围限制，内容需防XSS注入 |
| 接口安全 | 错误推测 + 边界值 | 需验证越权、篡改、注入等安全问题 |
